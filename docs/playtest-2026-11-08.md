# Hands-on browser playtest — 8 November 2026

I played all 13 active practice games with Playwright-driven clicks, typing,
sliders, and taps. I used the rendered board and controls, rather than injecting
answers into application state. This checks interaction and scoring flow; it
does not establish that the games are balanced or that synthesized audio sounds
good to a person.

| Game | Experience and outcome |
| --- | --- |
| Memory Grid | Clearest memory game. Recalled the visible cells and completed a 6/6 win. The blank retention phase works. |
| Number Order | Sorting the scattered numbers works. Its old zero-correct result was misleading; results now show ordered numbers and errors. |
| Odd One Out | The rotated target is readable and selectable. Completed a correct answer. |
| Pattern Complete | Originally six nearly identical cycles, so it felt repetitive. Now mixes alternating, paired, and three-item patterns. Completed the original flow and replayed the revised six-rule board to a 6/6 win. Existing seeded answer indices remain stable. |
| Dot Estimate | Simple and playable, but a fairly blunt guessing challenge. The visible starting estimate can now be submitted without moving the slider first. |
| Shape Recall | The shape and sliders previously lacked a clear mapping. Six numbered vertices now match the six controls; starting values also submit. |
| Time Recall | Completed a submission. Pulses now fit the reveal window and results include the missing error unit. |
| Rhythm Recall | Found a blocked answer pad. Fixed the hidden challenge metadata, required tap counts, and reveal length. Replayed all three rhythms through submission, then checked Rematch resets the taps. Locked answers now remain visible while the bot finishes. |
| Reaction Test | One of the most immediate games. Tested a false start, then completed four valid reactions and submitted. |
| Target Tap | One of the strongest arcade games. Completed all 12 targets with an intentional miss. Fixed the plural in the miss count. |
| Typing Sprint | Typed eight words through the actual input. Live speed/accuracy updates and deadline submission work. |
| Frequency Recall v2 | Completed all five rounds with slider guesses and inspected per-round scoring. Replay is available when browser audio needs a gesture. |
| Colour Recall v2 | Completed all five rounds. Swatch feedback is useful; the detailed colour metrics still demand more attention than the arcade games. |

My picks are Memory Grid, Reaction Test, and Target Tap: they communicate the
goal and the result fastest. The sensory games ask more of a new player, so
clear timing, point labels, usable defaults, and meaningful results matter more
than adding decoration.

## Limits

The local suite uses mocked backend data; four disposable-backend browser cases
remain skipped. The release continuation below adds real production two-user
authentication, matchmaking, submissions, ratings, and rematch coverage. I did not delete an account or
send messages to real people. Headless interaction cannot establish perceived
audio quality or human reaction-time fairness.

## Release continuation — 2026-11-11

Rhythm input now supports retrying a mistaken recording. Partial recordings
prevent tab switches; completed recordings remain available when switching.
The desktop/mobile regression exercises tap, retry, all three full recordings,
submission and rematch. Odd One Out tile buttons gained numbered accessible
labels and pressed state.

The hosted database's Rhythm reveal duration was corrected from 6500ms to
13000ms. A live production browser also exposed a missing network HMAC key
(analytics returned 403); a generated server-only sensitive environment variable
was configured for the release. Adaptive Turnstile keys remain unconfigured.

Production: https://quickduel-nu.vercel.app (gameplay release 9eb1d01). Completed
Rhythm practice on the deployed site, including three tap recordings and result.
Two fresh anonymous browser sessions then joined the same Memory Grid match.
The second submission returned 500 and left the match active: real play exposed
an ambiguous `season_id` variable in the season completion trigger. Applied a
forward migration renaming that variable; normal timeout recovered the old match.
Both sessions requested Rematch and submitted through visible game controls.
The rematch completed normally, showing matching opponent results and +15/-15
rating changes. The second session had no failed HTTP requests on that run.

A standalone SQL regression (all fixtures rolled back) also verified four normal
ranked completions, insert/update season points, the three-match daily pair cap,
and completion retry idempotency. No external player was messaged or matched.
Adaptive Turnstile keys are the remaining production configuration gap. Browser
automation does not establish human rhythm accuracy or perceived sound quality.

Live history correctly lists the normal result and timeout forfeit. Season play
also exposed a misleading #1 rank for provisional players omitted from the public
board. The screen now labels that status Provisional, explains that points are
saved, and gives an accurate empty-board message. Desktop/mobile browser coverage
checks that state; lint, typecheck and production build pass for this follow-up.
