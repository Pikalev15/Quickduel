# QuickDuel design and writing rules

QuickDuel is a competitive browser arcade, not a productivity SaaS or cognitive assessment. Keep its existing blue accent, dark/light themes, condensed Open Sans display face and Red Hat Display UI face.

- Use actual game mechanics and playable links to explain the product. Avoid stock feature grids, faux dashboards, decorative statistics and invented social proof.
- Use open, aligned rows for the game library and feature explanations. Reserve panels for game boards, settings, and information that needs a boundary. Tags use compact corners, not pills. Circular avatars, targets and progress indicators are functional exceptions.
- Write short instructions and concrete action labels. No em dashes, vague promotional filler, or technical implementation jargon in player copy. Prefer periods and colons. Do not claim cognitive benefits, perfect fairness or guaranteed matchmaking.
- Keep useful motion: navigation, answer confirmation, score feedback, and once-only scroll reveals. Respect reduced motion. Never delay gameplay or animate target positions.
- Review desktop and mobile screenshots against these rules before release; automated checks cannot judge taste.
